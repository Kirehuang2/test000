### 事故1: 2026-03-22 過電流

- モーター過熱（異臭あり）
- 教訓: I²t は Hall スパイクの発熱を考慮すべき。FF は速度リミッタに連動すべき

## 2. 保護レイヤー一覧

```
Layer 0: ハードウェア保護（ソフトウェア不要）
  - DRV8302 OCP/OVP/UVLO
  - 回生回路（39V トリガ）
  - 逆流防止ダイオード

Layer 1: 構造的制限（物理的にこれ以上出力できない）
  - 積分器クランプ ±0.05 → 最大ストール電流 2.87A
  - 円リミッタ 0.95 PU → 電圧上限
  - P コマンド安全クランプ → パラメータ上限
  - EnCl 起動遅延 → 1ms ゼロ電圧

Layer 2: ソフトウェア保護（異常検出→停止）
  - OC 保護（FOC-safe: IdqRef ゼロ方式 + グレース期間）
  - I²t 熱保護（raw I² + クランプ 0.12）
  - RPM 上限保護（4500RPM 超で停止）
  - 低電圧保護（12V/14V）
  - 温度保護（70/80/90°C）

Layer 3: 制御制限
  - 速度リミッタ（torque_max_speed_rpm）
  - FF 速度リミッタ連動（IdqRef=0 → FF=0）
  - output_derating → IdqRef AND FF に適用
```

## 3. 各保護の詳細設計

### 3.1 OC 保護（FOC-safe）

**目的:** 持続的な過電流の検出

**方式:** IdqRef をゼロにする + PI 積分リセット（Enable/Vabc_out を触らない）

**閾値:** OC_TRIP_PU = 0.40 PU (6.6A)
- 当初 0.30 PU で設計したが、正常運転中の Hall 遷移スパイクで IdFb が 0.33 PU に達し誤 trip → 0.40 に引き上げ
- |I|² = Id² + Iq² > 0.16 PU² で判定（個別軸ではなく合成電流）

**5ms 連続フィルタ:** 50 cycles (10kHz) 連続で閾値超過した場合のみ trip
- Hall スパイク (<1ms) では不発、持続的な過電流 (>5ms) で trip

**実装場所:** ADC callback (10kHz)

**起動グレース期間:** Enable 後 500ms は OC チェック無効

**動作:**
```
if (oc_grace_count > 5000) {
    float I2 = IqFb² + IdFb²;
    if (I2 > 0.16) {         // 0.40² = 0.16
        oc_sustain_count++;
        if (oc_sustain_count >= 50) {  // 5ms sustained
            overcurrent_fault = 1
            IdqRef = [0, 0]
            // PI integrals reset in FOC block
        }
    } else {
        oc_sustain_count = 0;
    }
}
```

**One_ms_Int 連携:**
```
if (overcurrent_fault) {
    IdqRef = [0, 0]  // 毎 1ms で強制ゼロ
    ff_scale = 0     // FF も停止
}
```

**FOC ブロック内:**
```
if (overcurrent_fault) {
    Id_integral = 0;  // PI 積分リセット（ストール電流防止）
    Iq_integral = 0;
    Vq_ff_lpf = 0;
}
```

**復帰:** E0 コマンドで overcurrent_fault クリア + i2t を 70% にリセット

**シナリオ検証:**
- 正常 T60, 500RPM: |I|²=0.06²+0.02²=0.004 << 0.16 → 不発 ✓ (実測確認 2026-03-24)
- Hall スパイク IdFb=0.33: |I|²=0.06²+0.33²=0.11 < 0.16 → 不発 ✓ (実測: trip せず)
- Hall スパイク IdFb=0.38: |I|²=0.06²+0.38²=0.15 < 0.16 → 不発 ✓ (実測: oc_peak_id=0.38, trip せず)
- ストール 2.87A (0.17PU): |I|²=0.029 << 0.16 → 不発 ✓
- P コマンド攻撃 (IdqRef=0.30): 持続 I=0.30PU → |I|²=0.09, 5ms 連続で不発。ただし I²t で長期保護 ✓
- 起動過渡: グレース 500ms → 不発 ✓
- FOC への影響: IdqRef ゼロ + PI リセット → ストール電流即停止 ✓ (実測確認)

### 3.2 I²t 熱保護

**目的:** モーター巻線の熱保護

**方式:** 1次遅れ熱モデル、raw I² + クランプ 0.12

**パラメータ:**
- I_rated = 0.20 PU (3.29A)
- τ_winding = 43.1s
- I2T_THRESHOLD = 0.04 × 43.1 = 1.724 PU²·s

**I² クランプ: 0.12 PU²**
```
理由:
  raw I² (スパイク含む): 0.57 PU² → クランプなしだと 38%/10s → 25s で trip（早すぎ）
  100Hz デシメーション: 0.002 PU² → 84s で保護不発動（遅すぎ）
  クランプ 0.12: スパイク (0.57→0.12) + 通常 (0.002) → ~93% 定常 → 60s で trip

  60s での巻線温度: ΔT ≈ 75°C → T = 100°C（限界 125°C 以内）
  → 保護が発動する前にモーターが損傷する温度に達しない ✓
```

**動作:**
```
float I2 = IqFb * IqFb + IdFb * IdFb;
float I2_clamped = I2 > 0.12f ? 0.12f : I2;
i2t_accumulator += (I2_clamped - i2t_accumulator / 43.1f) * 0.001f;
i2t_ratio = i2t_accumulator / 1.724f;

if (i2t_ratio >= 1.0) → trip (Enable=0, overcurrent_fault=1)
if (i2t_ratio >= 0.85) → derating (output_derating = 0.5→0.0)
if (i2t_ratio >= 0.70) → warning (output_derating = 1.0→0.5)
```

**output_derating の適用先:**
```
IdqRef[1] *= output_derating   // トルク指令を低減
ff_scale *= output_derating     // FF も低減
→ 両方を同時に低減しないと RPM 暴走が再発する
```

**シナリオ検証:**
- T30 正常運転: I²≈0.002 → clamp 不発 → E_ss=0.086 → 5% ✓ (永久運転可)
- ストール 2.87A: I²=0.029 → clamp 不発 → E_ss=1.25 → 72% → warning+derating ✓
- Hall スパイク 12.5A: I²=0.57 → clamp 0.12 → E_ss=5.17 → 300% → trip in 15s
  (ただしスパイクは断続的、実効 E_ss ≈ 93% → derating zone)
- 3.29A 持続: I²=0.04 → clamp 不発 → E_ss=1.724 → 100% → trip ✓
- 5A 持続: I²=0.092 → clamp 不発 → E_ss=3.97 → 230% → trip in 10s ✓

### 3.3 FF 速度リミッタ連動

**目的:** 速度リミッタが IdqRef=0 にしても FF が電圧を供給し続ける問題の防止

**方式:** FF を IdqRef の大きさに比例させる

**実装:**
```
// One_ms_Int (トルクモード):
float iq_cmd_raw = torque_ref_iq;          // 元の指令
iq_cmd = iq_cmd_raw;                       // 速度リミッタ適用前
// 速度リミッタ
if (speed > max) iq_cmd = 0;
else if (speed > 90% max) iq_cmd *= ratio;
// デレーティング
iq_cmd *= output_derating;
// OC フォルト
if (overcurrent_fault) iq_cmd = 0;

IdqRef[1] = iq_cmd;

// FF スケール = |iq_cmd| / |iq_cmd_raw|
if (fabsf(iq_cmd_raw) > 0.001f)
    ff_scale = fabsf(iq_cmd) / fabsf(iq_cmd_raw);
else
    ff_scale = 0.0f;
if (ff_scale > 1.0f) ff_scale = 1.0f;

// ADC callback (FOC):
Vq_ff = speed_pu * 0.52f * ff_scale;
```

**シナリオ検証:**
- T60, 300RPM: iq_cmd=0.06, raw=0.06 → ff_scale=1.0 → FF=full ✓
- 速度リミッタ作動 (500RPM): iq_cmd=0.0, raw=0.06 → ff_scale=0 → FF=0 → 減速 ✓
- 速度リミッタ半減 (475RPM): iq_cmd=0.03, raw=0.06 → ff_scale=0.5 → FF=50% ✓
- OC フォルト: iq_cmd=0 → ff_scale=0 → FF=0 ✓
- I²t デレーティング 50%: iq_cmd=0.03 → ff_scale=0.5 → FF=50% ✓

### 3.4 RPM 上限保護

**目的:** RPM 暴走の最終防壁

**方式:** SpeedFb_RPM > 4500 で Enable=0

**実装場所:** One_ms_Int (1kHz)

```
if (fabsf(SpeedFb_RPM) > 4500.0f) {
    overcurrent_fault = 1;
    Enable = 0;
    debug_enable_off_src = 9;  // RPM limit
}
```

**シナリオ検証:**
- 正常 500RPM: 不発 ✓
- FF 暴走 700RPM: 不発（4500 未満）→ 速度リミッタ + FF 連動で対応 ✓
- 制御不能暴走 5000RPM: trip ✓

### 3.5 P コマンド安全クランプ

**目的:** BLE 経由の危険パラメータ設定を防止

**実装:**
```
torque_ref_iq: |val| ≤ OC_TRIP_PU (0.30)
torque_ref_iq_max: 0 ≤ val ≤ OC_TRIP_PU (0.30)
Ki_id, Ki_iq: 0 ≤ val ≤ 50
```

## 7. v2 設計レビューで発見した追加事項

### 7.1 速度制御モード (control_mode=0) の FF 連動

v2 §3.3 はトルクモードのみ記述していたが、FOC の FF は両モード共通。
→ **対策**: 速度制御モードでも ff_scale を計算。SpeedControl_step 出力後の
   IdqRef[1] と output_derating 適用後の比から ff_scale を算出。

### 7.2 I²t の入力が IqFb/IdFb（LPF 後）

I²t で使用する IqFb/IdFb は ADC callback の LPF (α=0.1, 160Hz カットオフ) 後の値。
Hall スパイク（~456Hz）は部分的にしか通さない。
→ clamp 0.12 がこれをカバーするため問題なし。ただし明記。

### 7.3 P コマンドのパラメータ範囲

| パラメータ | 制限値 | 理由 |
|-----------|--------|------|
| torque_ref_iq | ±0.30 PU | OC 保護閾値 |
| torque_ref_iq_max | 0~0.30 PU | OC 保護閾値 |
| Ki_id, Ki_iq | 0~50 | 積分暴走防止 |
| Kp_id, Kp_iq | 0~10 | 制御不安定防止 |
| Kp_speed, Ki_speed | 0~10 | 制御不安定防止 |
| hall_angle_offset | ±1.0 rad | FOC 異常防止 |
| torque_max_speed_rpm | 0~4000 | RPM 保護 (4500) 以下 |
| speed_filter_alpha | 0.001~1.0 | ゼロ除算防止 |

### 7.4 var_registry の enable

`enable` を read-only に変更。P コマンド経由では Enable を設定できない。
E1 コマンド（overcurrent_fault チェック付き）のみで Enable 可能。
