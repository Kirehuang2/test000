### 高速域電流振動の診断経緯 (2026-03-29)

**棄却した仮説:**
1. ~~デカップリングω_eノイズ~~ → decouple ON/OFF で変化なし
2. ~~hall_offset DCずれ~~ → 0.15~0.30 で変化なし
3. ~~速度PI発振~~ → IqRef std=0.008 で安定、トルク制御でも振動
4. ~~電流フィードバックLPF帯域不足~~ → α=0.3 で2倍悪化（フィルタは振動を抑制していた）

**確定した真因: デッドタイム電圧歪み**
- セクタ別診断: Ialpha/Ibeta がセクタ依存で変動 → Park変換前に既に歪み → 角度は無罪
- 振動は速度に比例（fe増加でデッドタイム効果増大）
- 500ns デッドタイム × 6-PWM → ΔV=0.035PU/相 (設計値0.02 duty)

**DTC実装の経緯:**
1. 初回: 符号間違い + 相マッピング不整合 → 悪化
2. ハードウェア確認: Vabc[0]=C相, [1]=B相, [2]=A相; Iab[0]=A相, Iab[1]=B相
3. sign関数 → 低速でゼロクロスチャタリング → M500で300~700RPM振動
4. 線形補間方式（SPRAA87）に変更 → M500安定回帰、M2000で12%改善

**真因の再特定: FOC計算遅延 (2026-03-29深夜)**
- DTC だけでは M2000 |I|=1.33A → 0.3A 目標に未達
- コード全体精査で発見: ADCサンプル→duty反映まで ~200μs の計算遅延
- M2000 での角度遅れ = 1675 rad/s × 200μs = 0.335 rad = **19.2°**
- back-EMF (0.47PU) × sin(19°) = **0.15PU** の d軸漏洩電圧 → 電流PIの帯域外 (1600Hz vs 151Hz)
- angle advance (θ += ω_e × 200μs) で補償 → **|I|=0.071A** (95%削減)
- DTC は副因として有効（12%改善）、angle advance が主因解決策

**未解決の課題（次回以降）: DTC値と M0+E1 サーボ騒音のトレードオフ（既知課題#19）**

dtc_compのスイープ過程で重要な観察あり：
- M2000 では dtc=0.045 が最小 \|I\|（電流リップル最小、運転中は最も静か）
- **同じ dtc=0.045 で M0+E1（停止＋出力ON）すると サーボ音うるさい**
- 逆に dtc=0 にすると M0+E1 で完全無音だが M2000 で \|I\|=0.349A（リップル多）

**原因（推定）**: M0付近では実電流ほぼ0 → DTC線形ブレンドゾーン (±0.01PU) 内で sign 関数が頻繁に flip → 補償電圧チャタリング → 可聴音発生。dtc_comp が大きいほど chatter 振幅も大きく、騒音も大きい。

**対策候補**:
1. 速度/電流に応じた**適応 DTC**: 低速or低電流時は dtc=0、高速時に dtc=0.045 を smoothly blend
2. **線形ブレンドゾーン拡大**: 現±0.01PU を ±0.03PU 等に → low chatter
3. M0 検出で **DTC一時無効化**: speed_ref=0 検出時に dtc_comp を内部的に 0 へ
4. **dtc_enable のBLEトグル**: ユーザー判断で運転モード別に切替

**現状の妥協**: デフォルト 0.045（運転中の性能優先）。M0で静音重視なら BLE で `SET dtc_comp 0` 可能。

**未解決の課題（次回以降）: BLE/UART 安定性 @ 18kHz**

18kHz CPU 61%負荷 + UART RX FIFO trigger=MAX で BLE log rate が変動：
- パワーサイクル直後: 90+ samp/s（健全）
- 時間経過/再接続後: 9 samp/s に劣化、csum_fail 多発

試行錯誤：
- ✗ `RX_FIFO_TRIGGER_1`（バイト毎割込み）: BLE応答が更に悪化、要 revert
  - 推測: 1バイト割込みの過多で UART RX が CPU を圧迫
- ★ MAX のまま運用、**「電源リセットで復帰」**を運用回避策として採用

**保留中の調査項目**：
- UART RX FIFO trigger を `4` 等の中間値で試す
- BLE TX path の優先度・バッファ設定見直し（csum_fail 対策）
- DA14531 firmware と MCU 間のフロー制御強化
